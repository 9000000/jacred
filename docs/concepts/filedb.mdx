FileDB — встроенное хранилище JacRed без СУБД. Каждая раздача хранится как JSON-объект в файле на диске, а поиск работает через in-memory индекс `masterDb`. Это делает JacRed самодостаточным: не нужны PostgreSQL, SQLite или Redis.

## Структура директорий

```text
/app/                   (рабочая директория)
├── init.yaml           (рабочая копия из /app/config)
├── config/
│   └── init.yaml       (постоянный конфиг)
└── Data/                (изменяемые данные)
    ├── fdb/
    │   ├── AB/
    │   │   └── CDEF1234...json
    │   ├── BC/
    │   │   └── DEF56789...json
    │   └── ...
    ├── log/
    │   ├── fdb.2025-01-01.log
    │   └── fdb.2025-01-02.log
    ├── crontab
    └── run-job.sh
```

<Note>
  Бинарник JacRed ищет `init.yaml` в текущей рабочей директории. В Docker entrypoint создаёт `/app/init.yaml` из `/app/config/init.yaml`. FileDB всегда хранится отдельно в `/app/Data/fdb/`.
</Note>

## masterDb: in-memory индекс

При запуске JacRed загружает в оперативную память индекс всех ключей FileDB. Этот индекс называется `masterDb`. Он содержит компактные метаданные каждой раздачи для быстрой фильтрации без чтения с диска.

Полные данные (название, magnet, список файлов) читаются с диска только при необходимости.

## Шардирование: fdbPathLevels

Параметр `fdbPathLevels` задаёт глубину вложенности директорий для распределения файлов. При значении `2` (по умолчанию) файл с MD5-хешом ключа `ABCDEF...` хранится по пути:

```text
Data/fdb/AB/CDEF<хвост>.json
```

<ParamField path="fdbPathLevels" default="2" type="number">
  Количество уровней директорий (1-4). Значение 2 создаёт до 256 подпапок первого уровня. Рекомендуется не менять после первого заполнения базы.
</ParamField>

## Ограничение чтения: maxreadfile

<ParamField path="maxreadfile" default="250" type="number">
  Максимальное число записей, прочитанных из одного JSON-файла за один запрос. Защита от чрезмерного потребления памяти при очень больших шардах.
</ParamField>

## Логирование изменений

JacRed записывает все операции с FileDB (добавление, обновление, удаление) в ротируемые лог-файлы.

```yaml
logFdb: true
logFdbRetentionDays: 7
logFdbMaxSizeMb: 0
logFdbMaxFiles: 0
```

| Параметр | Описание |
| --- | --- |
| `logFdb` | Включить логирование изменений |
| `logFdbRetentionDays` | Дней хранения лог-файлов (0 = без ограничения) |
| `logFdbMaxSizeMb` | Макс. размер файла в МБ (0 = без ограничения) |
| `logFdbMaxFiles` | Макс. число файлов в ротации (0 = без ограничения) |

Логи создаются в `Data/log/fdb.YYYY-MM-DD.log`.

## Сохранение на диск

FileDB накапливает изменения в памяти и сбрасывает их на диск:

- **Cron-задача** `jsondb-save` вызывает `GET /jsondb/save` каждые 5 минут.
- **При синхронизации** через `syncapi`.

Принудительное сохранение вручную:

```bash
curl "http://localhost:9117/jsondb/save?devkey=YOUR_DEV_KEY"
```
